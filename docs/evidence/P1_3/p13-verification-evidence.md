## 3. Batas Verifikasi dan Pemisahan Tanggung Jawab

- **Domain P1.3:** Terbatas pada fungsi logika murni TypeScript (`deriveEpisodeScope`, `associateMessageToEpisode`, transisi status, `splitEpisode`, suppression helper, dan struktur audit). Tidak berinteraksi dengan database, network, browser, atau provider eksternal.
- **Transaksi & Persistence P1.4:** Pengujian atomic locking, PostgreSQL unique constraint (`complaints_primary_service`), rollback transaction, dan claim reservation diverifikasi secara terpisah pada suite integrasi P1.4 ([p14-verification-evidence.md](../P1_4/p14-verification-evidence.md)). Skenario 4 persistence menguji penambahan guard event setelah GENERIC, bukan flow reopen database.
- **Sesi Staf & Otorisasi:** Pengecekan sesi staf browser diuji pada P0.4–P0.6. Helper server `staff-episodes.server.ts` mengambil actor dari sesi Auth berdasarkan review statis.
- **UI & Dispatch P2/P3:** Tampilan inbox, rendering template balasan, webhook Telegram, dan worker pengiriman outbound berada pada Phase 2 dan Phase 3. Pada P1.3, seluruh hasil tetap `dispatchAuthorized: false`.
